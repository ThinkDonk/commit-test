# 阶段：浏览器执行与沉淀

## 前置

1. 通过 Skill 工具加载 `web-gui-tester`（黑盒方法论、P0-P3 分级、截图证据、报告格式）
2. 浏览器操作规则以 `control-browser` 为准（bootstrap、tab 管理、snapshot 优先）——web-gui-tester 第 5 原则已声明：冲突时工具自身规则赢
3. 两者都不可用 → 停下报告"缺浏览器工具"，不要用 curl 冒充

## 执行深度

默认 **P0 冒烟**：模块页面能打开、主流程步骤走通、关键反馈出现（列表刷新 / toast / 状态变化）。P1-P3 只在模块文件标注"重测要求"时执行。

## 命中模块（模块文件存在）

照文件里的「页面入口 → 导航 → 主流程步骤 → 验证点」走。步骤走不通时按「自愈」处理，不要硬套。

## 未命中但需测（现场探索 + 沉淀）

1. 从改动文件推断功能名（后端服务名 / 前端目录名）
2. 找页面：读前端路由配置，拿到路由和菜单名
3. 浏览器登录后按菜单导航到页面，走一遍主流程，记录每步
4. 探索完先**按 TEMPLATE.md 沉淀模块文件**，再照文件把流程完整走一遍（保证沉淀的步骤本身可用）
5. 探索失败（找不到页面 / 无入口）→ 报告"该改动无法页面验证"，归入降级清单

## 自愈（步骤失效时）

页面改版 / 路由变更导致沉淀步骤走不通：重新探索找到新路径，**更新模块文件**后再继续，同步更新 last-verified。禁止不更新文件、拿当次临时探索结果蒙混——知识库会因此腐烂。

## 报告格式

```markdown
# 集成测试报告：<范围>

## 环境
- 复用/启动了哪些服务、健康检查结果

## 结果总览
| 模块 | 结果 | 证据 |
|------|------|------|

## 通过
（每模块：走了哪些步骤、验证点）

## 失败
（复现步骤 + 截图 + 现象）

## 未覆盖
（文件清单 + 原因）

## 降级验证
（后端-only 改动：build/启动/日志结论）

## 沉淀
- 新建/更新了哪些模块文件
- 基线是否推进
```

截图与证据保存遵循 web-gui-tester 的要求：每个测试点必须有**看过的**截图为证。

## 基线更新

全部命中模块**通过**（失败可接受时须用户明示）→ 把 HEAD 记入 tested-commits.md。有失败 → 基线不动，下轮重测。
