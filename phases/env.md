# 阶段：环境准备

## env.md 结构

```markdown
# 环境信息：<项目名>

## 仓库与服务
| 角色 | 仓库/工作目录 | 启动命令 | 地址 | 就绪检查 |
|------|---------------|----------|------|----------|
| 后端 | <绝对路径> | <命令> | <URL> | <检查方式> |
| 前端 | <绝对路径> | <命令> | <URL> | <检查方式> |

## 登录
- 登录入口: <URL>
- 账号来源: <当前会话已提供 / 获准的本地凭据位置>

## 环境限制与已知事实
- <数据库/代理目标的核对位置，不记录连接密码>
- <用户明确禁止的配置改动、数据写入等>
- <就绪判据、已核实的启动差异及日期>
```

本次实际使用的版本、地址、进程/日志位置和操作写进 run；稳定启动知识保留在 env.md。

## 先核对，再复用或启动

1. 查项目约定及 env.md，核实前端实际请求目标、后端运行目录和当前服务状态。健康检查通过不等于运行了待测版本，也不等于业务页面可用。
2. 匹配的服务已运行时复用，不结束用户进程。若无法确认版本，在 run 标注，不据此推进提交基线；可继续独立调查。
3. 需要启动时使用项目现有命令，在后台启动并保留日志；Windows 按宿主规则隐藏辅助窗口。
4. 分段轮询就绪，采用已知启动耗时作为上限（缺省可取 3 分钟），长等待间保持进度沟通。超时检查日志和端口归属，不盲目重启。

连接串、数据库选择、代理目标、身份和权限按本次授权使用。不能为了通过测试擅自切换数据库或改全局测试配置；需要改变时先说明具体必要性及当前限制。用户明确禁止的配置保持不动。只读核对时避免输出密钥。

## 交互就绪

服务与运行版本核对后，用一个低影响、结果可观察的页面操作确认交互可用，例如展开菜单或执行只读查询，记录操作前后状态；已有 P0 场景满足时直接复用。页面能读取、截图能生成或工具调用返回成功，都不能单独证明输入已到达页面、业务动作已发生。

等待目标页面的具体就绪信号，如加载结束、目标控件可操作、预期数据出现；不把固定延时或全站 `networkidle` 作为统一成功条件。

只有出现点击无响应、动画停滞等异常时，才按当前工具允许的能力检查页面/框架上下文、遮挡、焦点、帧或事件派发。正常测试不强制安装探针；工具不允许的脚本或底层通道不得作为绕过手段。异常取证和重试规则见 [execute.md](execute.md)。

## 首次初始化

- 沿用已有项目知识目录；没有则建立 env.md 与实际需要的 modules/runs 记录。
- 从 AGENTS.md、README、启动配置和包脚本核实命令与地址，区分确认事实与待核实推断。
- 优先使用用户已提供的账号及仍有效的授权来源；缺少必要凭据才询问，不重复索要。忽略目录中也不默认复制密码。
- 说明实际使用的服务与目标后继续测试；环境准备本身不算业务验证。

收尾记录本次启动的服务是否保留，只有需要停止且能确认属于本次启动的进程时才处理。不得仅凭端口号结束未知进程。
