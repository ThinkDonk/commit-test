# 阶段：环境准备

## env.md 结构

```markdown
# 环境信息：<项目名>

## 后端
- 工作目录: <绝对路径>
- 启动命令: <命令>
- 端口/地址: <URL>
- 健康检查: <返回 200 即就绪的 URL>

## 前端
- 工作目录: <绝对路径>
- 启动命令: <命令>
- 地址: <URL>
- 健康检查: <返回 HTML 即就绪>

## 账号
- 用户名: <用户名>
- 密码: <密码>
- 登录入口: <URL>

## 已知坑
- <启动慢、既有警告噪音等>
```

## 复用判定（先探后启）

对每个服务先做健康检查探测，**通了就直接复用**——用户可能自己起过服务，绝不能杀掉重启。前后端都通 → 跳过启动直接进执行。

## 启动流程

1. 后台启动，日志写到可读文件
2. 轮询健康检查 URL，间隔 5 秒，上限 3 分钟（后端首次编译慢属正常）
3. 超时 → 读启动日志定位（端口占用/编译失败/依赖缺失），如实报告，不盲目重启
4. 前端同理，通常几秒内就绪

启动命令和目录以 env.md 为准，不要每次重新探索。

## 首次初始化（projects/<项目名>/ 不存在时）

1. 建目录 + `env.md` + `modules/`
2. 从项目 AGENTS.md / README / package.json / 启动配置推断前后端启动方式、端口
3. 健康检查选最稳定的探测点（swagger 页 / 前端首页）
4. **账号必须问用户**，不要猜、不要翻代码里可能的测试账号
5. 推断结果落盘 env.md 后，向用户复述一遍关键信息再启动

初始化本身不算测试，做完环境准备继续正常流程。
